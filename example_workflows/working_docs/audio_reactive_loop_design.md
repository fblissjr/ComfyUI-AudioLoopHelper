# audio_reactive_loop — design

Full-length **audio-reactive loop**: an init image animated under a frozen
audio track so its visible motion tracks the beat, for the entire length of the
track. Promoted from `docs/experimental/` to the top-level shipped surface
(`example_workflows/audio_reactive_loop.json`) after a full-length render
validated it.

User-facing runbook: `docs/experimental/audio_reactive_workflows.md`. This doc
is the design rationale (the *why*).

## What it is

The canonical `audio-loop-music-video_latent.json` topology, **unchanged** (it
passes every loop audit invariant — 44 OK), with a handful of widgets preset for
audio-reactivity. Generated/regenerated by `scripts/apply_audioreactive_loop.py`
(forks the canonical + applies the presets; every preset is `--flag`-overridable,
`--force` regenerates).

## Why keep the loop (vs the single-shot preview rig)

- The single-shot fork (`example_workflows/experimental/audio_driven_single_shot.json`,
  still experimental) renders one ~14 s window — fast, zero cross-iteration drift —
  for previewing the look.
- The loop renders the **whole track** (auto-sizes via
  `AudioLoopPlanner.total_iterations`) — required for real installation / DJ-set
  lengths. The default prompt is a single `0:00+:` entry; the schedule *can* evolve
  the visual across sections (add `M:SS+:` entries) but doesn't by default.
- Intended flow: preview/tune on the single-shot, render long-form here.

## Preset knobs + rationale

| Node | Knob | Value | Why |
|---|---|---|---|
| #1523 | `audio_to_video_scale` | 2.5 | amplifies how hard audio drives video attention (1.0 = neutral) |
| #508 | NAG `nag_scale` | 5 | canonical 11 is the documented distilled freeze-risk knob; 5 is safer for a motion-first render |
| #507 | NAG negative | motion + frame-quality | drops singer-specific tokens (faces / hands / mic) for a non-person default |
| #1269 | `first_frame_guide_strength` | 0.7 | per-iteration init re-anchor strength = the drift-vs-motion dial (= canonical) |
| #1615 | prompt schedule | single `0:00+:` entry | one look held for the whole render; add `M:SS+:` entries to evolve per section |

## The drift-vs-motion tradeoff (`first_frame_guide_strength`)

The loop re-anchors the init each iteration (`#1519 LTXVAddLatentGuide`, strength
= `#1269`). This **bounds** drift but doesn't eliminate it for a motion + stylized
subject:

- `1.0` = max identity stability, minimal motion freedom.
- lower = more motion, more cross-iter style drift (per-window sawtooth as the
  anchor pins the boundary frame while interior frames drift, plus the
  overlap-context channel carrying the prior window's already-drifted output
  forward).
- `0.7` is the shipped default (matches the canonical; a render preferred it over
  0.6). Tune **up** (0.8) if a stylized/painterly init drifts toward photoreal over
  the render; **down** (0.4–0.6) if motion is too stiff.

## Coupling ceiling

Native LTX 2.3 audio-reactivity is a **global, diffuse, loosely-coupled** influence
— "moves with the music," not frame-accurate per-beat lock. Concentrate it by:
simplifying competing motion in the scene, a big singular beat verb, higher
`audio_to_video_scale`, and loud (peaking) audio. Tight metronomic per-beat lock is
out of scope (would need structural audio-reference conditioning).

## Validation + promotion

Validated by a full-length audio-reactive render (the loop tracked the full track
and held style). Promotion criteria met: a clean-auditing top-level workflow, a
validating render, and documentation. The single-shot preview rig stays
experimental pending its own validation.
