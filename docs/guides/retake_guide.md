# Retake guide

Regenerate a `[start_time, end_time]` window of a previously generated
video without re-rendering the rest. Useful when one section came out
wrong but the surrounding content is good.

Workflow: `example_workflows/audio-loop-music-video_retake.json`.
Built by: `scripts/apply_audio_loop_retake.py`.

## When to use this

- Fix a few seconds of bad face frames, hand artifacts, or wardrobe
  glitches without re-running an 8-minute generation.
- Swap one phrase or one short scene to match a different prompt.
- Re-roll a problematic transition between two sections.

If you want to regenerate the full video at higher quality or at a
different resolution, the upscale workflow is the right tool, not retake.

## What's preserved vs. what regenerates

| Aspect | Behavior |
|---|---|
| Video frames inside `[start_time, end_time]` | Regenerated from noise, conditioned by the prompt |
| Video frames outside `[start_time, end_time]` | Frozen — held as context (`noise_mask=0`) |
| Audio | Passed through unchanged from the source mp4 |
| Resolution | Inherited from the source video (do not change) |
| Frame rate | Inherited from the source video |

The frozen region passes through one VAE encode/decode round-trip.
Drift introduced by that round-trip is typically imperceptible at LTX
quantization, but you may notice it on very high-frequency texture
detail.

## Setup

1. Open `example_workflows/audio-loop-music-video_retake.json` in ComfyUI.
2. On the **Prior generation (mp4)** `LoadVideo` node, replace
   `REPLACE_WITH_PRIOR_GENERATION.mp4` with the filename of the video
   you want to retake.
3. On the **Retake range** `LatentTemporalMask` node, set:
   - `start_time` (seconds) — where the retake region begins
   - `end_time` (seconds) — where it ends
   - `fps` — must match the source video's frame rate (default 25.0)
4. Edit the positive prompt (`CLIPTextEncode` upstream of
   `LTXVConditioning`) to describe what should appear in the retake
   region. Keep the rest of the workflow untouched.
5. Queue.

## Constraints inherited from production

The retake workflow uses the same patch chain and sampler as the
production loop workflows. The same constraints apply to the source
video and the prompt:

- **Length**: the source video's frame count must satisfy
  `(L - 1) % 8 == 0`. If the source was generated by an
  AudioLoopHelper workflow, this is already true. To check or derive
  a valid length for a target duration, use the
  `LTXAVTools.LTXFrameCalculator` node — input
  `(seconds, fps)`, output `(frames, latent, actual_seconds)`.
- **Resolution**: width and height divisible by 32.
- **Prompt**: must contain the word "singing" (or "are singing
  together"). LTX 2.3 audio-video cross-attention binds lip sync to
  this verb; without it, motion stalls.
- **`frame_rate`** stamped on `LTXVConditioning` (default 25.0).

## Audio behavior

Audio passes through from the source mp4 directly to
`VHS_VideoCombine`. The sampler does not see audio, and audio
cross-attention is not active during retake. This means:

- Audio is bit-perfect preserved (no re-encoding through the audio
  VAE).
- Lip sync inside the retake region is **not** explicitly enforced by
  AV cross-attention. The model relies on the surrounding fixed
  context for continuity.

If lip sync visibly drifts inside the retake range, that's the signal
that a future AV-aware retake variant is needed. Until then, keep
retake regions short relative to the surrounding context.

## Latent quantization to 8-frame chunks

The retake range snaps to LTX latent frames. With the default 8x
temporal compression and 25 fps:

- 1 latent frame = 8 video frames = 0.32 seconds.
- A 1.0-second retake window covers 4 latent frames, which decode to
  32 video frames = 1.28 seconds.
- Sub-second retake windows snap to multiples of 0.32 seconds.

The node's frame-index math is generous on inclusion: `start_latent =
int(start_time * fps / 8)` and `end_latent = int(end_time * fps / 8)
+ 1`, clamped to the latent length. Reversed or zero-width ranges
yield an all-zero mask (no-op) rather than raising — the workflow
won't crash on bad widget input, but it also won't regenerate
anything.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Output is byte-identical to input | `start_time >= end_time` (zero-width or reversed range) | Set `end_time > start_time` |
| Output is silent | `VHS_VideoCombine.audio` got disconnected during edits | Re-run `apply_audio_loop_retake.py` to restore wiring |
| Hard cut / color shift at retake boundary | Boundary frames not anchored | Acceptable for v0; future variant may add `LTXVAddLatentGuide` on boundary |
| Lip sync drift inside retake range | AV cross-attention not active during retake (Option A limitation) | Keep retake regions short; flag for future AV-aware variant |
| Workflow won't queue (size mismatch) | Source video's `(L - 1) % 8 != 0` | Trim or pad the source video |
| Output shows preprocessing artifacts | Source video was heavily compressed before loading | Re-export from prior generation at lower CRF |
